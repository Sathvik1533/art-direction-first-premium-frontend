# Reference Analysis Guide

Use this guide whenever a project supplies inspiration websites, competitor URLs, screenshots, or product references.

## Required analysis per reference

For each reference, record four things:

1. **Observed strength:** What specifically makes it feel authored, premium, clear, trustworthy, or memorable?
2. **Applicable principle:** What can this project learn?
3. **Page/behavior fit:** Which project surface can use that principle?
4. **Do-not-copy boundary:** What must remain unique to the reference?

Do not write “make it look like X.” Write “borrow X’s narrative pacing for the landing page” or “borrow Y’s information hierarchy for the case workspace.”

## Reference roles

Use references as role models for strengths, not as page-by-page costumes. Typical roles include:

| Role | Useful questions |
|---|---|
| Voice | How does the product speak? What does it believe? |
| Hero composition | What establishes the world in the first viewport? |
| Typography | How are scale and reading hierarchy controlled? |
| Atmosphere | How do color, depth, imagery, and motion create feeling? |
| Product visualization | How does the marketing site preview the real product? |
| Operational UI | How is dense information made scannable? |
| Trust | How are proof, limitations, and money explained? |
| Interaction | How do controls respond without visual noise? |
| System thinking | How are reusable rules made visible across pages? |

## Selection rules

Choose three to seven references with complementary strengths. Include no more than one or two direct competitors unless a competitive comparison is the project goal. Prefer references that clarify a design decision rather than references chosen only because they are attractive.

Never copy a reference’s layout, exact colors, font pairing, illustrations, wording, animations, or branded metaphor. If the project’s proposed hero could be mistaken for the reference with the logo removed, reject and redesign it.

## Synthesis rule

After analysis, write one synthesis sentence:

> Borrow [principle] from [reference A] for [project surface], [principle] from [reference B] for [behavior], and [principle] from [reference C] for [trust/voice], then express all of them through one original project visual world called [name].

The synthesis must produce a single identity, not a collage.
