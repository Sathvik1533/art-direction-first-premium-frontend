# Visual Concept Scorecard

Use this scorecard to compare visual concepts before implementation. Score each criterion from 1 to 5 and record evidence from screenshots, not adjectives.

## Scoring

| Score | Meaning |
|---:|---|
| 1 | Missing or actively harmful |
| 2 | Weak and generic |
| 3 | Competent but not distinctive |
| 4 | Strong and intentional |
| 5 | Memorable, ownable, and clearly justified |

## Criteria

| Criterion | Review question | Score |
|---|---|---:|
| Product truth | Does the concept visually express what the product actually does? |  |
| Point of view | Can someone sense what the product believes before understanding every feature? |  |
| Emotional premise | Does it create the intended feeling for the target user? |  |
| Distinctiveness | Is it recognizable without the product name or logo? |  |
| Brand ownership | Would this still belong to the project if the reference websites disappeared? |  |
| Voice | Do the typography and copy sound like one authored product? |  |
| Typography | Are display, interface, and data roles clear and restrained? |  |
| Scale | Is there purposeful contrast between large statements and precise details? |  |
| Whitespace | Does space create focus and tension instead of looking unfinished? |  |
| Materiality | Do surfaces, rules, shadows, and depth support the product metaphor? |  |
| Signature metaphor | Does the visual object explain product truth rather than decorate it? |  |
| Marketing/product link | Does the real workflow feel like the same world as the landing page? |  |
| Information clarity | Can users find the main action and understand the evidence path? |  |
| Interaction quality | Do motion and controls make the experience clearer or more useful? |  |
| Mobile integrity | Does the idea remain strong at the smallest target viewport? |  |
| Accessibility | Can contrast, focus, labels, zoom, and reduced motion be supported? |  |
| Performance | Can the visual effect be implemented without excessive weight or delay? |  |
| Originality | Does it avoid copying reference layouts, components, or metaphors? |  |
| Longevity | Can this visual system support all routes without exhausting the metaphor? |  |
| Quality bar | Does it credibly meet the project’s stated benchmark? |  |

## Decision rule

Do not choose a concept by average score alone. Reject a concept with a score below 3 in product truth, point of view, distinctiveness, marketing/product link, accessibility, or originality. A concept with fewer effects but stronger ownership should beat a visually busy concept that looks borrowed.

## Required comparison output

For each concept, include the total score, the three strongest dimensions, the three risks, the surfaces where it works best, and the changes required before implementation. Record the selected concept and rejected concepts in `DESIGN.md`.

## Generic-output test

Remove the logo, brand name, and product-specific words from the screenshot. Ask:

> Would this still be identifiable as a specific product with a specific point of view?

If the answer is no, the concept is not ready.
